# dresscode-quantum

npm-библиотека: `Quantum` — кванты, объекты с изменяющимся значением (лексика — в CONTEXT.md). Корень npm-пакета = корень репозитория; библиотека — в `lib/` (объявлена `lib/.dresscode`).

## Знания

- `lib/.dresscode` объявляет Bricks двумя альтернативными путями: `../node_modules/dresscode-bricks/lib` (этот проект) и `../../../node_modules/dresscode-bricks/lib` (npm-hoisting в потребителе); в каждом layout существует ровно один, другой молча пропускается.
- dresscodejs — НЕ devDependency проекта: для сборки используется глобальный бинарник (`~/.nvm/.../bin/dresscodejs`); `.yaxy` для тестов вызывает `bin: dresscodejs ~/test/...` (хост `quantum.tests`, браузерный mocha в test/index.html).
- `npm test` — node-харнес `test/node/run.js`: собирает `test/tests/Quantum.Quant.js` dresscodejs'ом (`-i` обязателен: dresscodejs 2.x не принимает позиционный аргумент) и прогоняет сьют (47 тестов; 1 намеренно красный — pin'ит нефикснутый 20260924-6 (пассивный transform), npm test будет красный до фикса) mocha bdd. Браузерный сьют (yaxy + `test/index.html` + `test/external/`) — для интерактива; `test` и `.yaxy` в .npmignore, в пакет не попадают.
- Зачем харнес сам ставит заглушки `document`/`window`/`location` и `global.chai`/`global.sinon`: собранный тестовый файл — один IIFE (Bricks/Quantum локальны IIFE), тестовый код берёт библиотеки из глобального скоупа; `Bricks.DOM.getEl` жадно вычисляет `doc || document`, samsam (sinon) требует `document.createElement`. chai — строго 4.x (5+ ESM-only, node 18 без require(ESM)); sinon 7.0.0 — та же, что в `test/external/`. `process.exit(failures)` в конце — страховка от реальных таймеров (напр. getTimer) в тестах.
- Кванты пассивны, пока нет ни одного слушателя: активность = `this._listeners.length > 0` (единый реестр `this._listeners` на все события, без флага; базового класса нет: `superclass` = Object). Первый слушатель активирует квант, последний — деактивирует; переходы — инлайновые в `Quantum.Quant` (setValue/getValue/addEventListener/removeEventListener), отдельных `_activate`/`_deactivate` нет.
- Подписка на «источники зависимости» (CONTEXT.md) — инлайновая в `Quantum.Quant`: родитель when-цепочки (его `prioritychange`, подписка при активации) + вложенный квант (`prioritychange`, подписка/снятие в setValue/add/remove при активности) + ресанхронизация `_parentValue` (кэш `c586975`); общих хуков нет, guard-проверки активности — 4 места (setValue/getValue/add/remove). `Array` и `Combinator` ИМЕЮТ override'ы add/removeEventListener (Array — `splice` родительского, Combinator — `prioritychange` детей). Cascade (активация/деактивация/свап вложенного источника) зафиксирован 3 тестами.
- `Bricks.inherit` без родительского класса → `superclass` = Object: `superclass.constructor.apply` в конструкторе `Quantum.Quant` — no-op (оставлен). `superclass.addEventListener/removeEventListener.apply` в Array/Combinator — делегирование в методы базового класса (`superclass` = `Quantum.Quant.prototype`, у которого `addEventListener` — own-свойство), работает как задумано; нативный EventTarget здесь ни при чём.
- Внутренние подписки между квантами идут через `Bricks.DOM.on` — шов осознанный, внутрисемейный (Bricks — наша библиотека): ctx-привязка поверх `addEventListener`, которая намеренно без `this` (единообразие с платформой). `Bricks.DOM.un`/`unAll` согласованы с cascade-деактивацией квантов (проверено репро 18/18: без осиротевших ссылок и skips); единственное ограничение: `unAll()` не видит прямые user-слушатели — квант, переживший `unAll()`, остаётся с устаревшим значением до remove/add-цикла.
- 51e84eb (2025): dispatch в `_fireEvent` идёт по снапшоту `this._listeners.slice(0)` — иначе снятие слушателя из собственного обработчика пропускало следующего.
- c586975 (2024): кэш `_parentValue` гарантирует один вызов modifier на каждое значение родителя (без него пассивный getValue переопрашивал бы modifier на каждый вызов).
- node_modules/dresscode-bricks — настоящий npm-пакет 0.2.10 (не symlink на соседний проект). `docs/adr/` — пустая папка: ADR 0001-0003 (шов Bricks.DOM, один реестр, без базового класса) раньше здесь описывались, но в репозитории их нет (todo 20260927-2).
- `series`/`getTimer` в node-тестах работают под `sinon.useFakeTimers` тестового файла (beforeEach): `setInterval`/`setTimeout`/`Date` фейковые, процесс не живёт; кэш `Quantum.getTimer` живёт на объекте `Quantum.$$_timers[timeout]` и переживает тесты — таймауты в разных тестах должны различаться.
- Контракт Array (2026-09-26): append/prepend — только массив, иначе TypeError; push — varargs, возвращает новую длину; в splice события идут с живого _value, slice() берётся после событий (мутации из обработчиков не затираются), но-оп не вызывает событий, отрицательный start нормализуется.
- JSDoc (по-русски) прописан в `lib/Quantum/` (2026-09-27): классы, публичные методы, функции index.js, события (`@event`/`@fires`), typedef `Quantum.ChangeEvent`; внутренние `_*`/`$$*` члены — без документации. При смене публичного контракта JSDoc обновляется вместе с кодом.
